# React 的钩子有哪些 [小米]

React 的钩子（Hooks）主要有以下几种，每个钩子都有特定用途：

1. **useState**
   - 在函数组件中声明状态变量。
   - 语法：`const [state, setState] = useState(initialState);`

2. **useEffect**
   - 在函数组件中执行副作用，如数据获取、订阅、DOM 操作等。
   - 语法：`useEffect(() => { /* 副作用 */ }, [dependencies]);`

3. **useContext**
   - 访问 React 上下文中的值，简化 `Context.Consumer` 的使用。
   - 语法：`const contextValue = useContext(MyContext);`

4. **useReducer**
   - 管理更复杂的状态逻辑，类似 Redux 的 reducer，适合状态变化较复杂的场景。
   - 语法：`const [state, dispatch] = useReducer(reducer, initialState);`

5. **useCallback**
   - 缓存函数，避免不必要的函数重建以优化性能。
   - 语法：`const memoizedCallback = useCallback(fn, [dependencies]);`

6. **useMemo**
   - 缓存计算结果，避免重复的高开销计算。
   - 语法：`const memoizedValue = useMemo(() => compute(), [dependencies]);`

7. **useRef**
   - 创建一个可变引用，保存 DOM 元素或任意值，不会触发重新渲染。
   - 语法：`const myRef = useRef(initialValue);`

8. **useLayoutEffect**
   - 与 `useEffect` 类似，但在 DOM 更新后同步触发，适合需要同步测量 DOM 的场景。
   - 语法：`useLayoutEffect(() => { /* 同步副作用 */ }, [dependencies]);`

9. **useImperativeHandle**
   - 与 `forwardRef` 搭配，定制暴露给父组件的实例值。
   - 语法：`useImperativeHandle(ref, () => ({ /* methods */ }));`

10. **useDebugValue**
    - 在开发工具中显示自定义 Hook 的调试信息。
    - 语法：`useDebugValue(value);`

# setState 是如何触发 rerender（diff） [小米]

`setState` 触发 React 组件重新渲染的过程大致如下：

1. **调用 `setState`**  
   React 将状态更新放入更新队列，并标记组件需要重新渲染。
2. **调度更新**  
   调度器（Scheduler）在合适的时机执行更新。
3. **生成新的虚拟 DOM**  
   基于最新的 `state`/`props` 生成新的 Virtual DOM。
4. **Diff 比较**  
   将新旧 Virtual DOM 进行比较，找出差异：
   - 同类型节点：仅更新不同的部分。
   - 不同类型节点：卸载旧节点并挂载新节点。
   - 列表节点：通过 `key` 优化重排和更新。
5. **更新真实 DOM**  
   React 生成最小化的 DOM 操作集合并应用到真实 DOM。
6. **生命周期钩子**  
   - 更新前可能触发 `shouldComponentUpdate`（类组件）。  
   - 更新后触发 `componentDidUpdate`（类组件）。

通过虚拟 DOM 和 diff 算法，React 只更新真正变化的部分，从而保持高效。

# React 生命周期 [小米]

React 的生命周期方法主要适用于 **类组件**，它们定义了组件在不同阶段的行为。随着 React 向 **函数组件** 迁移（尤其是通过 React Hooks），生命周期的管理方式有所变化，但理解类组件的生命周期仍然很重要。下面讲解 **类组件** 的生命周期，并介绍如何在函数组件中使用 **`useEffect`** 替代这些生命周期方法。

## 1. 生命周期概述

React 组件的生命周期可分为三个阶段：

- **挂载阶段（Mounting）**：组件实例化并插入 DOM。
- **更新阶段（Updating）**：组件因 `props` 或 `state` 变化而重新渲染。
- **卸载阶段（Unmounting）**：组件从 DOM 中移除。

---

## 2. 类组件的生命周期方法

#### 2.1 挂载阶段（Mounting）

这些方法在组件第一次被创建并插入 DOM 时调用：

##### `constructor(props)`
- 在组件实例化时调用，常用于初始化状态或绑定方法。
- 只在挂载时调用一次。

```js
constructor(props) {
  super(props);
  this.state = { count: 0 };
}
```

##### `static getDerivedStateFromProps(nextProps, nextState)`
- 在每次渲染前调用（包括首次渲染和更新）。
- 返回一个对象以更新状态，或返回 `null` 表示不更新。
- 静态方法，无法访问实例 `this`。

```js
static getDerivedStateFromProps(nextProps, nextState) {
  if (nextProps.someValue !== nextState.someValue) {
    return { someState: nextProps.someValue };
  }
  return null;
}
```

##### `render()`
- 必需方法，返回描述 UI 的 React 元素。
- 不应在此修改 `state` 或执行副作用。

##### `componentDidMount()`
- 组件挂载并渲染到 DOM 后调用一次。
- 适合执行副作用（如数据请求、事件订阅等）。

```js
componentDidMount() {
  console.log("Component mounted");
  // 执行异步操作，如数据请求
}
```

---

#### 2.2 更新阶段（Updating）

当组件的 `props` 或 `state` 发生变化时会触发：

##### `static getDerivedStateFromProps(nextProps, nextState)`
- 与挂载阶段相同，用于在更新前根据新的 `props` 派生 `state`。

##### `shouldComponentUpdate(nextProps, nextState)`
- 在每次更新前调用，决定组件是否需要重新渲染。
- 返回 `true` 继续渲染，返回 `false` 跳过渲染（可用于性能优化）。

```js
shouldComponentUpdate(nextProps, nextState) {
  return this.state.count !== nextState.count;
}
```

##### `render()`
- 与挂载阶段一致，用于输出最新的 UI。

##### `getSnapshotBeforeUpdate(prevProps, prevState)`
- 在 `render` 之后、DOM 更新之前调用。
- 可读取 DOM 信息（如滚动位置），其返回值会作为 `componentDidUpdate` 的第三个参数。

##### `componentDidUpdate(prevProps, prevState, snapshot)`
- 组件更新并应用到 DOM 后调用。
- 适合基于最新 `props`/`state` 继续执行副作用，或根据 `snapshot` 做操作。

```js
componentDidUpdate(prevProps, prevState, snapshot) {
  console.log("Component updated");
  // 比较前后的 props 和 state，执行相应操作
}
```

---

#### 2.3 卸载阶段（Unmounting）

组件从 DOM 中移除时调用：

##### `componentWillUnmount()`
- 在组件卸载和销毁前调用。
- 用于清理副作用（取消订阅、清除计时器等），是类组件中最后执行的生命周期方法。

```js
componentWillUnmount() {
  console.log("Component will unmount");
  // 清理副作用操作
}
```

---

## 3. 函数组件与 `useEffect` 的替代

借助 React Hooks，函数组件也能管理状态和副作用。`useEffect` 可以模拟类组件的生命周期行为：

#### `componentDidMount` 的替代
传入空依赖数组 `[]`，副作用仅在挂载时执行一次。

```js
useEffect(() => {
  console.log("Component mounted");
}, []); // 仅在组件挂载时触发
```

#### `componentDidUpdate` 的替代
传入依赖数组，依赖变化时执行，类似更新阶段。

```js
useEffect(() => {
  console.log("Component updated");
}, [someProp]); // 仅当 someProp 改变时触发
```

#### `componentWillUnmount` 的替代
`useEffect` 返回清理函数，在卸载时调用，用于清理副作用。

```js
useEffect(() => {
  return () => {
    console.log("Component will unmount");
  };
}, []); // 仅在卸载时清理
```

---

### 4. 总结

- **类组件生命周期**：
  - 挂载：`constructor`、`getDerivedStateFromProps`、`render`、`componentDidMount`
  - 更新：`getDerivedStateFromProps`、`shouldComponentUpdate`、`render`、`getSnapshotBeforeUpdate`、`componentDidUpdate`
  - 卸载：`componentWillUnmount`

- **函数组件生命周期（基于 `useEffect`）**：
  - 空依赖数组模拟挂载及卸载清理。
  - 指定依赖数组模拟更新行为。

理解生命周期有助于管理副作用、优化性能与资源清理。即便函数组件已成为主流，掌握类组件生命周期仍是深入理解 React 的关键。




## 4.虚拟列表的实现原理 [小米]

虚拟列表（Virtual List）是一种优化长列表渲染性能的技术。它通过仅渲染视口范围内的元素，而不是将整个列表中的所有元素都渲染到 DOM 中，从而显著提高了性能，尤其是在列表项数量非常庞大的情况下。这种技术常用于需要滚动的长列表，比如社交媒体、消息列表等。

### 虚拟列表的实现原理

1. **仅渲染可见部分**
   - 在传统的长列表渲染中，所有的项都会被渲染到 DOM 中，导致性能问题，特别是列表项很多时。
   - 在虚拟列表中，只会渲染当前视口中可见的元素。当用户滚动时，新的可见元素会被动态加载和渲染，同时，视口外的元素会被卸载。

2. **计算可见范围**
   - 使用浏览器的滚动事件监听器来获取当前的滚动位置。
   - 根据可见区域的高度和单个列表项的高度，计算出哪些项应该渲染，哪些项应该卸载。

3. **动态创建和销毁 DOM 元素**
   - 根据滚动位置，决定哪些列表项需要显示。渲染那些在视口范围内的元素，而不是渲染整个列表。
   - 当用户滚动时，更新渲染的列表项，卸载那些滚动出视口的项，并加载那些滚动进视口的新项。

4. **计算位置**
   - 对于固定高度的列表项，计算所有项的总高度，并使用偏移量来确定哪些项应该显示。例如，可以通过 `scrollTop` 和 `itemHeight` 来确定当前视口的位置。
   - 对于不同高度的列表项，通常需要存储每个列表项的高度，并动态计算。

5. **虚拟化的布局**
   - 对于 **固定高度的列表项**，虚拟列表的实现较为简单，可以通过 `scrollTop` 和固定的项高度来确定渲染项的位置。
   - 对于 **不固定高度的列表项**，需要一个更复杂的布局系统，记录每个列表项的实际高度，并动态计算哪些项应该被渲染。

### 主要实现步骤

1. **初始化列表项**
   - 根据列表的总高度和每个列表项的高度（或者根据每个项的实际高度）来计算可见区域内的项数。

2. **滚动事件监听**
   - 监听滚动事件，当用户滚动时，计算出当前视口内的起始项和结束项，然后重新渲染对应的项。
   
3. **渲染可见项**
   - 渲染当前视口范围内的所有项，并将它们放置在正确的位置。

4. **更新位置信息**
   - 使用 `transform` 或 `position: absolute` 来定位每个元素的位置，这样可以避免影响其他元素的布局。
